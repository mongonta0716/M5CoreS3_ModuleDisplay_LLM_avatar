# 音声解析・描画・検証

[READMEへ戻る](../README.md)

## 音声解析

ローカル音声入力は共通の`MicLipSync`を使います。CoreS3内蔵マイクとAtomのEchoBase／PDMUnitの音声を
16kHzのステレオ形式のバッファへ渡し（モノラル入力はM5Unifiedで複製）、
[m5stack-avatar-mic](https://github.com/mongonta0716/m5stack-avatar-mic)と同じ256点FFTで
312.5〜3750Hz（bin 5〜60）の音量を集計して口を動かします。
ModuleLLMではLinux側で同じDSPを実行し、結果をUARTでCoreS3へ送ります。
音量に応じた感度調整と口の開閉の平滑化を行い、無音が続くと口を閉じます。
さらに32msごとにLPCで声の共鳴周波数F1・F2を推定し、日本語の5母音に応じて
口の幅・高さ・丸みを変えます。判定が弱い区間は音量による開閉に戻ります。
口の横の吹き出しに、推定した母音を「あ・い・う・え・お」で表示します。
無音や判定が不確かな区間、口パクデモ中は「…」を表示します。
初期設定でも動作しますが、CoreS3はB、AtomはAの単押しで、本人の声と周囲の雑音に合わせて調整できます。

### 口形と推定の範囲

| 母音 | Avatarの口の表現 |
| --- | --- |
| あ | 幅のある大きな縦開き |
| い | 横に広く薄く開く |
| う | 小さく丸くすぼめる |
| え | 横に広い角丸の形 |
| お | 縦長の丸い形 |

弱めの声や中程度の確信度でも母音の幅・丸みの特徴を残し、音量は主に高さへ反映します。
無音へ移る際には閉じた形へ戻し、形は滑らかにつなぎます。
吹き出しの文字は口の形と同じ判定結果を使うので、形が似ている場合と母音判定の違いを確認できます。
これは音声認識の確定結果ではなく、
口パク用の簡易推定です。ささやき声・無声化した母音・雑音・速い発話・高い声では
判定できないことがあり、その場合は音量による開閉に戻ります。
初期の母音中心値は調整用の初期値で、全話者に共通する境界値ではありません。

### フォルマント抽出と調整

母音解析は16kHzの音声を低域フィルターに通して8kHzへ間引き、32ms窓、
プリエンファシス、Hamming窓、10次自己相関LPC、LPC多項式の根からの共鳴周波数・帯域幅の抽出を行います。
スペクトルの山が重なる場合でもF1/F2を分けるため、極の周波数を使います。
単一音やスペクトルの傾きを拾う極を除外し、調整では静音の中央値と外れ値を除いた代表的なF1/F2の組を使います。
保存前に、各母音の測定値の65%以上が同じ母音として判別できるかも検査します。
調整用の特徴抽出は以前の静音しきい値で止めず、今回測った静音レベルで声を選別します。
同じ母音の2回分をまとめて評価し、息つぎ中の音は収集しません。
3秒×2回の手順で、実機ログから5母音の調整完了と新しい設定の保存を確認しています。
CoreS3の旧ピーク抽出版で保存した設定は消さずに読み込めますが、新しい解析に合わせてBで再調整してください。
有声判定と2フレーム以上の継続判定を使い、通常のFFT音量処理はそのまま残します。
LPCの背景と根からの共鳴周波数の算出は[PraatのLPC資料](https://praat.org/manual/Sound__To_LPC__autocorrelation____.html)と
[フォルマント変換の資料](https://praat.org/manual/LPC__To_Formant.html)を参照しています。

## 描画ライブラリ

母音の口形・補間、日本語吹き出し、複数画面の同期描画は、
`M5Unified-Avatar`リポジトリの`m5avatar::MultiDisplayAvatar`へ移しました。
このアプリの`DualDisplayAvatar`は操作・デモ・性能ログとDSPの母音型の変換を担当します。
マイク解析と個人調整値の保存は引き続きアプリ／ModuleLLM側です。

PlatformIOはGitHub上の描画APIを含むコミット`e92d62012a015511567e8ae76f042428e018a6d8`から
ライブラリを取得します。隣のディレクトリへのローカルチェックアウトは不要です。
ライブラリだけで使う場合は`MultiDisplayAvatar.h`をincludeし、初期化済み画面を
`addDisplay(display, reservedBottom)`で登録して、`setVowel`・`setMouthOpenRatio`・
`setBalloon`を設定しながら`update(millis())`を呼びます。

## Hello World → Avatar（ModuleDisplay有効時）

以下は`USE_MODULELLM=0`、`USE_MODULEDISPLAY=1`での動作です。
`USE_MODULEDISPLAY=0`では本体LCD・本体スピーカーだけを使います。
CoreS3 + ModuleDisplayで、HDMIモニターに紺色背景・白い枠・中央の`Hello World`を
**2秒間表示してから、アニメーションするAvatarへ切り替えます**。
HDMI側は320×180で描画し、ModuleDisplayで1280×720へ4倍拡大します。
Avatarは4:3の顔を240×180で描画し、モニター上では960×720の大きさで中央表示します。
まばたき・視線・呼吸を更新し、等倍描画に比べてHDMIへ転送する画素数を約1/16、
従来の640×360描画に比べて約1/4に減らします。
CoreS3本体にも同じ表情・動きのAvatarを表示します。下40ドットのボタン領域を避け、
上部320×200に約267×200の顔を中央配置します。両画面は共通の状態で順に描画します。

## メモリと拡大表示

顔のキャンバスは1bit、転送用バッファは16bit×高さ8ピクセルです。1280×720の16bitフルフレームをCoreS3側には確保しません。
等倍時、外部画面の正方形キャンバスは960×960で約115,200バイト、転送バッファは15,360バイトです。
既定の4倍拡大では240×240で7,200バイト、転送バッファは3,840バイトになります。
本体画面のキャンバスは267×267で約9,078バイト、転送バッファは4,272バイトです。
キャンバスはPSRAMを利用可能な設定にし、転送バッファは内部RAMに置きます。

拡大率を変更する場合は、`platformio.ini`の対象環境の`-DAVATAR_HDMI_SCALE`を変更して再ビルドします。
既定の`m5stack-cores3`（`m5stack-cores3-hello`も同じ）は`4`、従来の`m5stack-cores3-legacy`は`1`です。

| 設定 | 論理解像度 | 論理的な顔のサイズ | HDMI出力 |
| --- | --- | --- | --- |
| `1` | 1280×720 | 960×720 | 1280×720 |
| `2` | 640×360 | 480×360 | 1280×720、2倍拡大 |
| `4`（既定ビルド） | 320×180 | 240×180 | 1280×720、4倍拡大 |

低解像度モードではModuleDisplayがハードウェアで拡大します。720pの16:9比率に合わせて論理解像度も16:9にし、その中央に4:3の顔を表示します。
従来の`m5stack-cores3-legacy`ビルドでは、起動時に外部画面用バッファの確保に失敗した場合、2倍、4倍の低解像度モードへ順に切り替えて再試行します。HDMI出力は1280×720のままです。
すべて失敗した場合や、動作中の再確保に失敗した場合は該当画面の描画を停止してログにエラーを表示し、他の画面の描画を続けます。

### AtomS3のRAM使用量

[AtomS3](https://docs.m5stack.com/en/core/AtomS3)はPSRAMを搭載しませんが、
ESP32-S3の内部SRAMを使います。SoCのSRAMは512KBで、コードやシステム領域とも共有します
（[ESP32-S3データシート](https://www.espressif.com/sites/default/files/documentation/esp32-s3_datasheet_en.pdf)）。
現在の`AtomS3-noPSRAM`ビルドの静的データRAMは69,300バイト（約67.7KiB）で、
PlatformIOが示す320KiBに対して21.1%です。この数値にはタスクのスタックやDMAなどの動的確保は含みません。

128×128の顔は1bitキャンバス約2KiBと、128×8・16bitの転送バッファ約2KiBで描画します。
M5GFXはPSRAMがない場合に内部RAMへ確保するため、描画ライブラリの変更は不要です。
起動・録音描画開始・調整開始／保存／リセット時の`Atom memory:`ログで、内部RAMの空き・最小空き・
最大連続領域とPSRAM総容量を確認できます。

回転対応版のAtomS3＋PDMUnitの実測では、PSRAM総容量0の状態で録音・描画開始直後の内部RAM空きは
300,700バイト（約294KiB）、その時点までの最小空きは295,572バイト、最大連続領域は270,324バイトでした。
90度・180度への回転後も空きはそれぞれ300,632バイトでした。
描画は約15fpsで、ユーザーによる調整保存・口パク復帰の確認も完了しています。
この構成では内部RAMで動作できています。静的RAMの表示と実行時ヒープの表示は集計対象が異なるため、
320KiBから静的使用量を引いた値がそのまま実行時の空きになるわけではありません。

## 実装ファイル

以下のパスはリポジトリのルートを基準にしています。

- `src/atom_s3.cpp` / `src/AtomAudio.h`: AtomS3／AtomS3Rの起動、入力選択、録音と画面操作。
- `src/CalibrationButton.h` / `src/AtomDisplaySettings.h`: Atomのボタン判定、向きの保存と復元。
- `src/main.cpp`: 旧診断用アプリのCoreS3／ModuleDisplay初期化、タッチ・USBシリアル入力。
- `src/hello_world.cpp`: 既定ビルドの起動・タッチ・表示構成と音声入出力の切り替え。
- `src/MicLipSync.h`: M5Unifiedによるローカルマイク録音、完了通知からのFFT処理。
- `src/MicFftAnalyzer.h`: FFTの帯域集計、感度調整、口の開閉の平滑化。
- `src/VowelAnalyzer.h` / `src/LpcFormants.h`: 有声判定、LPCの極からのF1/F2推定、母音判定の継続処理。
- `src/VowelModel.h`: 母音モデル・特徴値と判定処理。口形と吹き出しの描画はライブラリの`VowelMouth`が担当します。
- `src/VowelCalibration*.h`: 段階的な声の調整とNVS保存。
- `lib/AvatarMicFFT`: avatar-micから取り込んだFFTとMITライセンス。
- `src/AppConfig.h`: マイク・ModuleDisplayの有無、HDMIの論理解像度・ハードウェア拡大率。
- `src/DualDisplayAvatar.*`: ライブラリ描画APIへの接続、DSPの母音型の変換、操作・デモ・性能ログ。

通常のCoreS3／Atom構成はM5Unified-Avatarのコミット`e92d62012a015511567e8ae76f042428e018a6d8`に固定しています。
ライブラリの`MultiDisplayAvatar`が、各画面の論理解像度に合った顔とキャンバスを作り、
共通のアニメーション状態を使って順番に描画します。既存の`Avatar::start()`の描画タスクは起動しません。
`m5stack-cores3-legacy`だけは比較用に以前のコミット`69e8045bf98f49509611563b9d16ea433c7b8ea7`を参照します。

## ビルド成果物

既存の`scripts/copy_firmware.py`も使用します。ビルド後に結合ファームウェアが`.pio_build_firmware/`へ保存されます。
現在のアプリも旧診断用アプリも実行時のファイルシステムを使用しないため、SPIFFSの生成・同梱を行いません。
`data/`は現在空で、追加の画像・音声ファイルは不要です。

通常の`pio run -t upload`はブートローダー・パーティション・アプリを書き込みます。
`.pio_build_firmware/`の結合binはフラッシュ全体のサイズに埋めたイメージで、通常アップロードとは別です。
保存済みの調整値・画面の向きを残す更新には通常のPlatformIOアップロードを使ってください。

## テスト

リポジトリのルートで実行します。ホスト側に`clang++`、または`CXX`で指定するC++コンパイラが必要です。

```sh
bash scripts/test_native.sh
```

ASan／UBSanを有効にして、次の処理を検証します。

- FFT：無音・音声帯域・帯域外・感度の復帰・最大振幅・時刻の周回
- 母音推定と調整：5母音の合成音、雑音・単一音の除外、共鳴の分離、調整成功・失敗、息つぎ、時刻の周回
- UARTとモデル：フレーム境界・CRC・セッション・古い結果の除外・保存・入力条件の一致
- Atomのボタン：単押し・ダブルクリック・長押しの優先順位、判定境界、遅延した更新、時刻の周回

ModuleLLMのビルド・プロセス試験・実機配置は[ModuleLLMガイド](../modulellm/README.md#ビルドと試験)を参照してください。
描画ライブラリ側の口形・実フレームバッファ試験は[M5Unified-Avatar](https://github.com/mongonta0716/M5Unified-Avatar)で管理しています。
合成音での試験結果は、実際の話者に対する認識精度を保証するものではありません。

## 実機で確認した範囲

AtomS3R＋EchoBaseでは、表示・起動音・口パク、Aの単押し／3秒長押し、
調整案内・保存・口パクへの復帰を実機で確認済みです。
AtomS3＋PDMUnitでも、表示・口パク、Aからの調整案内・保存・口パクへの復帰を確認しました。
ダブルクリックによる回転とCalの誤開始がないこと、USBの抜き差し後に保存した向きで
Hello World・Avatarが表示され、口パクが動くことも確認済みです。
AtomS3Rの回転追加版はビルド確認済みです。

### CoreS3とModuleDisplayの描画速度

変更前の640×360・2倍拡大では2026-10-17の実機で約5.8fps・平均描画時間約172msとなり、表示・動き・Aの発音・
再生後の口パク復帰をユーザーが確認済みです。
現在の320×180・4倍拡大では約10.3fps・平均描画時間約96.6msとなり、更新速度は約1.8倍になりました。
こちらも表示・動き・Aの発音・再生後の口パク復帰をユーザーが実機確認済みです。

母音解析追加後の実測は約10.1fps・平均描画時間約98msです。
2026-10-17に、本人の声での調整・保存、母音に応じた口の形の変化、
Aの発音と再生後の口パク復帰をユーザーが実機確認済みです。
その後の起動ログで保存済み設定のNVS読み込みを確認しています。
形の差を強めて吹き出しを追加した版も約10.1fpsで動作しています。
両画面の母音表示が正常で「あ・う・え」の口の形も見分けやすくなったことを、ユーザーが実機確認済みです。

これらは記載した構成・版での測定です。HDMI出力の60Hzは、Avatar自体の更新速度とは別です。
